# Architecture Research: v2.6 Pipeline Rewrite

**Research date:** 2026-03-09
**Milestone:** v2.6 Pipeline Rewrite
**Question:** How should the new per-driver pipeline be structured? What are the component boundaries and build order?

---

## Current Architecture (Confirmed from Codebase)

```
EstimatePair (two parsed JSONs)
    └── NarrativePipeline.run()
            ├── _run_analysis()     → AnalysisResult  [1 LLM call, all categories]
            ├── _run_writer()       → DraftNarrative  [1 LLM call, all categories]
            ├── _check_quality()    → QualityReport   [deterministic, no LLM]
            └── _run_compliance_loop() → DraftNarrative  [0-2 LLM calls]
                    └── _finalize()  → FinalNarrative
```

**Files:**
- `pipeline/orchestrator.py` — `NarrativePipeline` class, all pass coordination
- `pipeline/passes/analysis.py` — analysis pass, `sample_line_items()`, fuzzy category matching
- `pipeline/passes/writer.py` — writer pass, `build_writer_input()`, JSON parsing/repair
- `pipeline/passes/compliance.py` — compliance rewrite pass
- `pipeline/quality.py` — `QualityEvaluator`, GATE-01 through GATE-05
- `pipeline/models.py` — `AnalysisResult`, `DraftNarrative`, `DriverNarrative`, `FinalNarrative`, etc.
- `bid_comp/core.py` — `run_bid_comp()` entry point, category classification, `top_deltas`

## New Architecture (v2.6 Target)

```
EstimatePair (two parsed JSONs)
    └── CostDriverPipeline.run()
            ├── 1. build_trade_context()     → TradeContext  [no LLM]
            │       └── recap_by_category from both estimates
            │           + trade_summary fallback (SF final-draft only)
            │
            ├── 2. identify_cost_drivers()   → List[CostDriver]  [no LLM]
            │       └── sort by abs(delta) descending, take top N
            │
            ├── 3. map_driver_items()        → List[DriverWithItems]  [no LLM]
            │       └── for each driver: collect all line items from that category
            │           + verify line items sum ≈ category total
            │
            ├── 4. run_driver_passes()       → List[DriverAnalysisResult]  [N LLM calls]
            │       └── for each driver: own context window, own LLM request
            │
            ├── 5. run_summary_pass()        → SummaryResult  [1 LLM call]
            │       └── all driver analyses + grand totals + scope gaps → executive overview
            │
            └── 6. run_quality_rewrite()     → SummaryResult  [0 or 1 LLM call]
                    └── QualityEvaluator check → rewrite once if fails, else return as-is
                        └── assemble_final_narrative()  → FinalNarrative
```

## Component Boundaries

### `TradeContext` (new data model)
- Contains: `primary_by_category: Dict[str, float]`, `comparison_by_category: Dict[str, float]`, `grand_total_delta: float`, `source: Literal["trade_summary", "recap_by_category", "synthesized"]`
- Built from parser JSON, no LLM
- One per pipeline run

### `CostDriver` (new data model)
- Contains: `category: str`, `primary_total: float`, `comparison_total: float`, `delta: float`
- Ordered by `abs(delta)` descending
- Deterministic, no LLM

### `DriverWithItems` (new data model)
- Contains: `driver: CostDriver`, `primary_items: List[LineItem]`, `comparison_items: List[LineItem]`, `verification_ok: bool`, `verification_note: str`
- `verification_ok = True` if `sum(items) ≈ driver.primary_total` (within 2% tolerance)
- Built from parser JSON, no LLM

### `DriverAnalysisResult` (new data model, replaces per-category `CategoryAnalysis`)
- Contains: `category: str`, `narrative: str`, `key_items: List[str]`, `methodology_note: Optional[str]`
- One per cost driver, generated by one LLM call
- Pydantic model → use `generate_structured()`

### `SummaryResult` (new data model, replaces `DraftNarrative`)
- Contains: `overview: str`, `suggested_followups: List[str]`, `scope_observations: List[str]`
- Generated by final summary LLM call
- Pydantic model → use `generate_structured()`

## Data Flow

```
Parser JSON (primary)  ──┐
Parser JSON (comparison) ─┼── build_trade_context() ──→ TradeContext
                          │
TradeContext ─────────────┤── identify_cost_drivers() → List[CostDriver]
                          │
Parser JSON (both) ───────┴── map_driver_items() ──────→ List[DriverWithItems]

For each DriverWithItems:
  DriverWithItems + TradeContext ──→ run_driver_pass() ──→ DriverAnalysisResult

All DriverAnalysisResults + TradeContext ──→ run_summary_pass() ──→ SummaryResult

SummaryResult ──→ QualityEvaluator.evaluate() ──→ QualityReport
QualityReport (if failed) ──→ run_quality_rewrite() ──→ SummaryResult (rewritten)

SummaryResult + List[DriverAnalysisResult] ──→ assemble_final_narrative() ──→ FinalNarrative
```

## Build Order

1. **New data models** — `TradeContext`, `CostDriver`, `DriverWithItems`, `DriverAnalysisResult`, `SummaryResult` in `pipeline/models.py`
2. **Trade context builder** — `build_trade_context()` in new `pipeline/passes/trade_context.py`
3. **Cost driver identifier** — `identify_cost_drivers()` in new `pipeline/passes/cost_drivers.py`
4. **Driver item mapper** — `map_driver_items()` in `pipeline/passes/cost_drivers.py`
5. **Per-driver LLM pass** — `run_driver_pass()` in new `pipeline/passes/driver_analysis.py` + `driver_analysis_v1` prompt template
6. **Final summary LLM pass** — `run_summary_pass()` in new `pipeline/passes/summary.py` + `final_summary_v1` prompt template
7. **Quality rewrite** — rebuild `pipeline/passes/compliance.py` as `run_quality_rewrite()` (single-pass, strict threshold)
8. **New orchestrator** — `CostDriverPipeline` in `pipeline/orchestrator.py` (replace `NarrativePipeline` or rename to avoid breaking imports)
9. **Assemble final narrative** — `assemble_final_narrative()` maps `SummaryResult + List[DriverAnalysisResult]` → `FinalNarrative`

**Why this order:** Models first (everything depends on them). Pure data builders next (no LLM, testable in isolation). LLM passes after (depend on data models). Orchestrator last (depends on all passes). Final narrative assembly last (consumes orchestrator output).

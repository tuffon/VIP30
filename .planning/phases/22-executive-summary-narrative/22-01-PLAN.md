<objective>
Update writer_pass_v1 prompt from v2.3 to v2.4 to fix two quality regressions:

**Regression 1:** The user prompt sends `Overall Direction: {overall_delta_direction}` and `Confidence: {confidence}` as raw data fields. The LLM echoes `primary_higher` verbatim — producing "Overall direction: primary_higher. See key drivers below for details." instead of a professional paragraph.

**Regression 2:** The 7-pair APPROACH EXAMPLES table is in the system prompt but framed as optional inspiration with caveats ("not a closed list"). The LLM ignores it and leads with dollar amounts instead. The approach-pair framing must be mandatory — sentence 1 MUST open with loss type and approach difference, not with "the largest variance is in X."

Fixes:
1. Remove `Overall Direction` and `Confidence` raw fields from user prompt
2. Add anti-echo and anti-forward-reference rules to CRITICAL RULES
3. Add APPROACH PAIR REQUIREMENT after the 7-pair table in the system prompt, making approach-first sentence 1 mandatory (not optional)
4. Strengthen the CRITICAL RULES sentence 1 instruction to explicitly reference the APPROACH EXAMPLES table

Output: Both writer_pass_v1.json files updated to v2.4.
</objective>

**Change 1 — Remove `Overall Direction` and `Confidence` raw field lines from the user prompt.**

Find in the `user` string:
```
Analysis Results:
Overall Direction: {overall_delta_direction}
Confidence: {confidence}
```
Replace with:
```
Analysis Results:
```

These fields are derived data that the LLM cannot use to produce natural language — they only get echoed verbatim. The LLM already has full category amounts and top cost drivers to infer direction and confidence from the data.

**Change 2 — Add anti-echo and anti-forward-reference rules to CRITICAL RULES.**

Find in the `user` string the CRITICAL RULES block. It currently starts with:
```
CRITICAL RULES:
- USE ACTUAL ESTIMATE NAMES EVERYWHERE
```

Add these two new rules at the TOP of the CRITICAL RULES list (before the existing rules):
```
- NEVER echo raw field labels or internal values into narrative — do not write phrases like "Overall direction: primary_higher", "Confidence: high", or any other field-name: value pattern from the input
- NEVER write forward references like "See key drivers below for details" or "Refer to the analysis below" — include all relevant content directly in the paragraph
```

**Change 3 — Make approach-pair selection mandatory in the system prompt.**

In the `system` string, find the closing caveat after the 7-pair table:
```
These are EXAMPLES, not a closed list. Use language that accurately describes the specific approach difference you observe. If the data suggests a different characterization (e.g., "tear-out and replace" vs "patch and repair", or "full system replacement" vs "component-level fixes"), use that instead.
```
Replace with:
```
These are EXAMPLES, not a closed list. Use language that accurately describes the specific approach difference you observe.

APPROACH PAIR REQUIREMENT: Sentence 1 of the overview MUST apply one of these approach pairs (or a close equivalent you derive from the data) as the fundamental framing. Do NOT lead sentence 1 with a dollar amount, a category name, or "the largest variance is in X." The approach characterization comes FIRST — it is the lens through which the entire overview is written.
```

**Change 4 — Strengthen the sentence 1 CRITICAL RULE in the user prompt to reference the approach table.**

In the `user` string, find the CRITICAL RULES sentence 1 instruction:
```
- overview sentence 1: OPEN WITH LOSS TYPE AND AFFECTED AREAS, then state the fundamental APPROACH DIFFERENCE (restoration vs repair, replacement vs repair-in-place, etc.)
```
Replace with:
```
- overview sentence 1: OPEN WITH LOSS TYPE AND AFFECTED AREAS, then state the fundamental APPROACH DIFFERENCE — select the most applicable pair from the APPROACH EXAMPLES table in the system prompt (e.g., "full restoration vs targeted repair", "replacement-in-kind vs repair-in-place") and use that framing. Do NOT lead with a dollar amount or "the largest variance is in X."
```

**Change 5 — Bump version from 2.3 to 2.4.**

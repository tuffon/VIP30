# Phase 34.1: exact category preservation no umbrella remapping in bid comp - Research

**Researched:** 2026-03-11
**Domain:** Exact parsed category preservation in BidComp and pipeline category logic
**Confidence:** HIGH

## Summary

This is a focused corrective phase. The parser is not inventing the fake umbrella categories. The remapping is happening deterministically in shared-python after parsing.

The exact sources are:
- `packages/shared-python/vip_shared/bid_comp/core.py`
  - `VERISK_CATEGORY_ORDER`
  - `XACTIMATE_CATEGORY_CODE_MAP`
  - `CATEGORY_KEYWORDS`
  - `_map_category()`
  - `_aggregate_categories()`
- `packages/shared-python/vip_shared/pipeline/passes/trade_context.py`
  - `_map_category()`
  - `_extract_category_totals()`
  - `_extract_recap_evidence()`
  - `_extract_trade_summary_evidence()`
- `packages/shared-python/vip_shared/pipeline/passes/cost_drivers.py`
  - section line-item grouping still relies on mapped categories

The raw parser output clearly shows real category labels such as:
- `DOORS`
- `WINDOWS - SLIDING PATIO DOORS`
- `GLASS, GLAZING, & STOREFRONTS`
- `CABINETRY`
- `FINISH CARPENTRY / TRIMWORK`

The current code collapses those into synthetic umbrella labels such as:
- `Doors / Windows / Glass`
- `Cabinetry / Millwork`

That means the problem is not ambiguous. The phase should remove category identity remapping from the bid-comp path and preserve exact parsed labels.

## Existing Code Surfaces

### BidComp category identity
- `packages/shared-python/vip_shared/bid_comp/core.py`
  - `VERISK_CATEGORY_ORDER` is a synthetic canonical category list
  - `_aggregate_categories()` rewrites recap item labels through `_map_category()`
  - `_build_category_table()` currently uses the pipeline `TradeContext` totals, which still inherit remapped categories

### Pipeline category identity
- `packages/shared-python/vip_shared/pipeline/passes/trade_context.py`
  - recap rows are mapped through `_map_category()`
  - trade-summary rows are mapped through `_map_category()`
  - synthesized fallback also maps through `_map_category()`
  - the result is that `TradeContext` already contains normalized umbrella categories rather than exact parsed ones

### Driver mapping
- `packages/shared-python/vip_shared/pipeline/passes/cost_drivers.py`
  - selected driver categories are currently keyed by the normalized category names from `TradeContext`
  - section-item fallback grouping also depends on mapped categories

### Tests affected
- `packages/shared-python/tests/test_trade_context.py`
- `packages/shared-python/tests/test_cost_drivers.py`
- `packages/shared-python/tests/test_cost_driver_pipeline.py`

These tests currently assume the normalized umbrella category model and will need to be rewritten around exact parsed labels.

## Key Technical Findings

### 1. The fake categories are deterministic code artifacts
This is good news. The issue is easy to isolate because there is no parser ambiguity and no model behavior involved. The category rewriting is entirely inside Python code.

### 2. The fix is conceptually simple but will change comparison semantics
Today multiple real estimate categories can collapse into one umbrella category. Removing that remap will likely:
- split previous large driver buckets into several real categories
- change top-driver ordering
- make some cross-estimate mismatches visible instead of silently merged

That is the expected and desired result for this phase.

### 3. The hardest decision is matching policy, not implementation
If category labels differ between the two estimates, strict exact matching means they should remain separate for now. This phase explicitly prefers fidelity over forced alignment. A later alias layer can be added separately if desired.

### 4. Trade summary should preserve raw trade/category identity
The Phase 34 work correctly made `trade_summary` the preferred evidence source, but it still flowed through the old category remap path. This fix phase should preserve the raw trade identity instead of mapping it into umbrella buckets.

## Recommended Plan Split

### Plan 34.1-01: Remove umbrella remapping from category identity
Scope:
- stop using `_map_category()` style consolidation for recap/trade category identity in the bid-comp pipeline path
- preserve exact parsed category labels in `TradeContext`
- add tests that explicitly fail if fake umbrella categories appear

Why first:
- exact category identity is the root fix everything else depends on

### Plan 34.1-02: Align driver selection, BidComp output, and regression suite to exact labels
Scope:
- update top-driver selection and visible category table generation to use exact parsed labels
- keep unmatched categories explicit
- update regression coverage for exact labels and absence of umbrella outputs

Why second:
- once identity is correct, the ranking/output layer can be safely realigned

## Validation Architecture

### BidComp output tests

## Constraints for Planning

- No parser extraction changes
- No new alias layer in this phase
- No synthetic canonical category taxonomy in the bid-comp path
- Exact parsed category titles are the source of truth even when that exposes mismatches

# Phase 34.1: exact category preservation no umbrella remapping in bid comp - Context

**Gathered:** 2026-03-11
**Status:** Ready for planning

<domain>
## Phase Boundary

Remove deterministic umbrella remapping from the bid-comp and pipeline category path so category output uses the exact parsed category titles from `recap_by_category` and `trade_summary` rather than synthetic consolidated labels. This phase is about fidelity of category identity in BidComp and the category-first pipeline, not parser extraction changes or broader taxonomy design.

More specifically, the user wants the bid comparison to stop converting real estimate categories into made-up umbrella buckets such as `Doors / Windows / Glass` and `Cabinetry / Millwork`. The correct behavior for this phase is to preserve the category titles exactly as they appear in the parsed recap or trade summary structures and let mismatches remain visible instead of being hidden by consolidation logic.

</domain>

<decisions>
## Implementation Decisions

### Exact category identity
- Category titles used by bid comp must be 1:1 with the parsed category titles from `recap_by_category` and `trade_summary`.
- No umbrella consolidation is allowed in the bid-comp pipeline path.
- Labels such as `Doors / Windows / Glass` and `Cabinetry / Millwork` are considered invalid synthetic outputs for this phase because they are not the actual parsed category titles from the estimates.
- The current `VERISK_CATEGORY_ORDER`, `XACTIMATE_CATEGORY_CODE_MAP`, `CATEGORY_KEYWORDS`, and `_map_category()` based consolidation should be removed from the bid-comp comparison path for category identity purposes.

### Source preference
- If `trade_summary` exists, use its exact category rows as the preferred category source because it already provides category titles plus associated line items.
- If `trade_summary` does not exist, use the exact category labels from `recap_by_category`.
- `trade_summary` should not rename categories into shared umbrellas; it should preserve the actual trade/category labels found in the parsed JSON.

### Matching behavior
- Exact parsed labels are more important than synthetic alignment.
- If one estimate has `DOORS` and another has `WINDOWS - SLIDING PATIO DOORS`, those should not be silently collapsed into one fake umbrella category in this phase.
- Unmatched categories should remain explicit instead of being hidden by consolidation.
- If a later aliasing layer is needed, it must be explicit, approved, and separate from this phase. It is not part of the immediate fix.

### Analysis and top drivers
- The analysis page should be built from exact parsed category titles, not remapped umbrella categories.
- Top cost drivers should be ranked from those exact categories only.
- Driver narratives and summary synthesis must follow the same exact-category driver set rather than a consolidated taxonomy.

### Claude's Discretion
- Exact internal data-shape changes needed to preserve raw category identity through `TradeContext`, BidComp category rows, and top-driver ranking.
- Whether the exact preserved key should come from trade code + trade label, trade label alone, or recap `item` label, as long as the output remains faithful to the parsed source and does not invent umbrella labels.
- Exact regression-test layout needed to prove synthetic umbrella categories no longer appear.

</decisions>

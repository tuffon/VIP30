Create `apps/vip-parse/src/rules/` directory with `__init__.py` and `models.py`.

In `models.py`, define these Pydantic BaseModel classes:

**Enums:**
- `Severity(str, Enum)`: CRITICAL, NOTABLE, INFORMATIONAL — exactly 3 tiers per INTL-03
- `AlertType(str, Enum)`: MISSING_OP, SCOPE_IMBALANCE, DEPRECIATION_MISMATCH, LARGE_UNSPECIFIED, OP_STRUCTURE_MISMATCH, PRICE_LIST_MISMATCH — alert categories
- `PatternType(str, Enum)`: PARTIAL_VS_FULL_RESTORATION, SYSTEMATIC_PRICING_DIFFERENCE, SCOPE_ASYMMETRY — structural pattern types

**Emphasis models:**
- `EmphasisFlag(BaseModel)`: category (str), severity (Severity), delta (float), abs_delta (float), pct_of_total_variance (float), reason (str — why flagged, e.g. "Top variance driver: 32.1% of total variance")
  - Severity assignment rules:
    - CRITICAL: pct_of_total_variance >= 25% OR abs_delta is the single largest
    - NOTABLE: pct_of_total_variance >= 10% (and not critical)
    - INFORMATIONAL: in top 20% but below 10%

**Alert models:**
- `AlertTag(BaseModel)`: alert_type (AlertType), severity (Severity), title (str — short label, e.g. "Missing O&P in carrier estimate"), detail (str — one sentence explanation), affected_amount (Optional[float] — dollar impact if calculable)

**Pattern models:**
- `StructuralPattern(BaseModel)`: pattern_type (PatternType), description (str — what was detected), evidence (List[str] — specific data points supporting the pattern), estimated_impact (Optional[float] — dollar estimate if possible)

**Diagnostic follow-ups:**
- `DiagnosticFollowUp(BaseModel)`: trigger (str — what variance triggered this), action (str — specific next step, NOT a recommendation, e.g. "Request contractor's O&P breakdown"), priority (Severity — same 3-tier system), category (Optional[str] — related category if applicable)

**Ranked impact table:**
- `RankedImpactRow(BaseModel)`: rank (int), category (str), primary_amount (float), comparison_amount (float), delta (float), abs_delta (float), pct_of_total_variance (float), flags (List[str] — severity labels of any EmphasisFlags on this category)
- `RankedImpactTable(BaseModel)`: rows (List[RankedImpactRow]), total_primary (float), total_comparison (float), total_delta (float), total_abs_variance (float)

**Top-level result:**
- `SignalBundle(BaseModel)`: ranked_impact (RankedImpactTable), emphasis_flags (List[EmphasisFlag]), alert_tags (List[AlertTag]), structural_patterns (List[StructuralPattern]), diagnostic_followups (List[DiagnosticFollowUp]), flags_capped (bool — True if flags were capped at 5)

In `__init__.py`, export: RulesEngine (will exist after Task 2), SignalBundle, EmphasisFlag, AlertTag, Severity.

**Critical design rules:**
- All List fields use `Field(default_factory=list)`, never mutable default
- All float money fields use `round(x, 2)`
- EmphasisFlags list capped at 5 (top 5 by pct_of_total_variance)
- AlertTags list NOT capped (all detected alerts fire)
- DiagnosticFollowUps ordered by priority (CRITICAL first)

**Part A: Build structural pattern detectors** (`src/rules/patterns.py`)

Create module with pure functions for pattern detection. Each takes MethodologyResult and returns List[StructuralPattern]:

1. `detect_partial_vs_full_restoration(methodology: MethodologyResult) -> List[StructuralPattern]`:
   - Compare scope alignment: if primary has significantly more scope items (>30% more by count or >20% more by dollar amount), flag as partial restoration on comparison side (or vice versa)
   - Evidence: cite specific scope-only items and their totals
   - Check line_matches: if many matched items have large quantity differences (>50% delta), suggests one side scoped partial work

2. `detect_systematic_pricing(methodology: MethodologyResult) -> List[StructuralPattern]`:
   - Analyze line_matches where both sides have amounts: calculate per-match price ratio
   - If >60% of matched items show the same directional bias (primary consistently higher or lower), flag as systematic pricing difference
   - Evidence: cite match count, average ratio, and examples
   - Also check: if price_list_differs is True, note the different price lists as contributing factor

3. `detect_scope_asymmetry(methodology: MethodologyResult) -> List[StructuralPattern]`:
   - Check scope_alignment: if primary_only_total or comparison_only_total is >15% of the respective estimate total (from delta_breakdown), flag
   - Different from partial_vs_full: this is about specific missing items, not overall scope approach

Top-level function: `detect_patterns(methodology: MethodologyResult) -> List[StructuralPattern]` that calls all three and returns combined list.

**Part B: Build RulesEngine** (`src/rules/engine.py`)

Create class `RulesEngine` with method `evaluate(methodology: MethodologyResult) -> SignalBundle`.

The engine orchestrates 5 evaluation steps:

1. `_build_ranked_impact(delta_breakdown: DeltaBreakdown) -> RankedImpactTable`:
   - Convert DeltaBreakdown.categories to RankedImpactRow list
   - Assign rank (1-based) by abs_delta descending (already sorted from Phase 9)
   - Calculate total_abs_variance = sum of all abs_delta
   - Verify pct_of_total_variance sums to ~100%

2. `_flag_emphasis(ranked_impact: RankedImpactTable) -> List[EmphasisFlag]`:
   - Determine top 20% threshold: flag categories in top ceil(N * 0.2) by abs_delta
   - Assign severity per rules in models.py docstring:
     - CRITICAL: pct_of_total_variance >= 25% OR rank == 1
     - NOTABLE: pct_of_total_variance >= 10%
     - INFORMATIONAL: in top 20% but below 10%
   - Cap at 5 flags (take top 5 by pct_of_total_variance)
   - Generate reason string: "Top variance driver: {pct}% of total variance (${abs_delta:,.2f})"

3. `_detect_alerts(methodology: MethodologyResult) -> List[AlertTag]`:
   Fire alert tags based on deterministic rules:

   a. **MISSING_OP**: If one estimate has O&P (structure_type != NONE) and other doesn't → CRITICAL
   b. **OP_STRUCTURE_MISMATCH**: If both have O&P but op_treatment_differs → NOTABLE
   c. **DEPRECIATION_MISMATCH**: If depreciation_approach_differs → severity based on impact:
      - CRITICAL if one is ACV and other is RCV
      - NOTABLE if both ACV/RCV but settings differ
   d. **SCOPE_IMBALANCE**: If scope_alignment has >$5,000 unmatched on either side → NOTABLE
      - CRITICAL if >$15,000 unmatched
   e. **LARGE_UNSPECIFIED**: If "Other / Unclassified" category in delta_breakdown has pct_of_total_variance > 15% → NOTABLE
   f. **PRICE_LIST_MISMATCH**: If price_list_differs → INFORMATIONAL

   Each alert gets a human-readable title and detail string.

4. `_detect_patterns(methodology: MethodologyResult) -> List[StructuralPattern]`:
   - Delegate to `patterns.detect_patterns(methodology)`

5. `_generate_followups(emphasis_flags, alert_tags, structural_patterns) -> List[DiagnosticFollowUp]`:
   Generate actionable next steps for each signal:

   - For each CRITICAL/NOTABLE EmphasisFlag: "Verify {category} line items — ${abs_delta:,.2f} variance ({pct}% of total)"
   - For MISSING_OP alert: "Request {estimate}'s O&P breakdown to determine if overhead and profit are included in line item pricing"
   - For DEPRECIATION_MISMATCH: "Confirm depreciation methodology with both estimators — ACV vs RCV directly affects recoverable amount"
   - For SCOPE_IMBALANCE: "Cross-reference scope with loss assessment — {count} items totaling ${total:,.2f} appear in only one estimate"
   - For each StructuralPattern: follow-up specific to pattern type
   - For LARGE_UNSPECIFIED: "Request category breakdown for unclassified items — ${amount:,.2f} cannot be attributed to specific trades"
   - For PRICE_LIST_MISMATCH: "Confirm both estimates use the same price list and effective date"

   Sort by priority (CRITICAL first, then NOTABLE, then INFORMATIONAL).

**Main `evaluate()` method orchestrates all 5, sets flags_capped, and returns SignalBundle.**

**Critical rules:**
- NEVER fabricate data not in MethodologyResult — if field is missing, skip that rule
- All float calculations use round(x, 2)
- All lists sorted deterministically before returning
- Log what fires and what doesn't (debug level)
- Import from methodology.models, NOT from bid_comp
- Threshold constants defined as class-level constants (not magic numbers)

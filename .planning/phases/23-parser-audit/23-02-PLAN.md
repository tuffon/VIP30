  <action>
Read and analyze all available JSON outputs from plan 23-01. For each successful parse:

1. **Read `run_log.json`** to know which files succeeded and which failed.

2. **For each successful JSON file**, extract and record:
   - `estimate_name` — was it captured?
   - `case_metadata` keys — which metadata fields populated vs null/missing?
   - `sections` count and list of `section_name` values
   - Total `line_items` count across all sections
   - `section_totals.validation_delta` — non-zero means parser computed total ≠ declared total
   - `grand_total_areas` — populated or null?
   - `coverage` — populated or null?
   - `recaps_and_summaries` sub-fields: which of `summaries_by_coverage`, `recap_tax_op`, `recap_by_room`, `recap_by_category`, `trade_summary` are populated vs null?
   - Any `errors` fields in sections

3. **For failed files**: record the error type (crash vs empty output vs partial).

4. **Group findings by doc type**: rough-draft, contractor-final, StateFarm.

5. **Identify patterns**:
   - Which fields the rough-draft parser reliably captures
   - Which fields are consistently null or missing across all types
   - Whether final-draft and StateFarm PDFs produce degraded or failed output

Write analysis notes (intermediate, not final report). Use Python or direct file reading — whichever is faster.

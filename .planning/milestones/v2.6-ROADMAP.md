# Milestone v2.6: Pipeline Rewrite

**Status:** ✅ SHIPPED 2026-03-11
**Phases:** 29–34, 34.1
**Total Plans:** 13

## Overview

Four phases (plus two inserted phases 33 and 34.1) to replace the monolithic analysis→writer→rewrite pipeline with a stepped, cost-driver-first architecture. Phase 29 builds the trade context layer from parser recap data. Phase 30 identifies cost drivers by dollar delta and maps line items with verification. Phase 31 implements per-driver LLM passes with isolated context and structured output. Phase 32 adds the final summary LLM pass, rebuilds the quality rewrite as single-pass, and wires the new `CostDriverPipeline` as a drop-in replacement. Phase 33 locks the parser recap/trade-summary contract and refreshes goldens. Phase 34 recenters the pipeline on category-first evidence from `trade_summary` and `recap_by_category`. Phase 34.1 removes umbrella remapping so category identity is exact throughout.

## Milestone Summary

**Decimal Phases:**

- Phase 34.1: Exact category preservation (inserted after Phase 34 for urgent umbrella-label fix)

**Key Decisions:**

- [29] Inline `normalize_money` + `normalize_label` in each `passes/` module to eliminate all module-level `bid_comp` imports — circular dependency resolved without architectural changes
- [29] Lazy-load `bid_comp.core` constants via `importlib.import_module()` inside `_get_core_constants()` — called at function invocation time after full module graph initialization
- [30] `kalyvas` verification threshold `>=1` (not `>=2`) — kalyvas recap has only `O&P Items` group; Overhead & Profit total comes from subtotals with no matching line item cat codes; only Painting passes
- [31] No JSON repair in `driver_pass.py` — `generate_structured()` exception propagates to caller; Phase 32 handles failed drivers with `analysis unavailable` entries
- [32] Cache key includes `quality_notes` — rewrite requests must never reuse the initial summary cache entry
- [32] Driver-pass failures isolated per category — final output keeps category ordering and emits explicit fallback
- [34] Trade summary is the preferred category evidence source, but recap totals remain authoritative when both exist
- [34] Deterministic ranking stays entirely upstream of the LLM
- [34] BidComp category tables now use the same trade-context totals as the pipeline path
- [34.1] `TradeContext` preserves exact parsed category titles and skips recap rollup subtotal rows
- [34.1] Exact category identity continues through BidComp tables and raw line-item fallback mapping

**Issues Resolved:**

- Pipeline↔bid_comp circular import at module load time (lazy-import pattern)
- SF GCO&P surcharge (~16-20% of grand total) appearing as category overcounts in tolerance tests
- Umbrella labels (`Doors / Windows / Glass`, `Cabinetry / Millwork`) leaking into visible pipeline output
- StateFarm wrapped-description landing in `notes` instead of description
- `_build_fallback_result()` and `_finalize_with_error()` placeholder text in output

**Issues Deferred:**

- Rough-draft `insured_name` not extractable (parser limitation, v2.7+)
- `price_list` suffix truncation in parser output (v2.7+)
- 3 lachman_sf sections with declared-vs-computed rounding deltas (v2.7+)
- `tests/test_migrations_constraints.py` 2 unrelated failures expecting `vip30-web` service naming
- `tests/test_coverage.py` 1 unrelated lachman_sf item-count mismatch with matching totals

**Technical Debt Incurred:**

- `_normalize_money` + `_get_core_constants()` duplicated in each `passes/` module (trade_context.py, cost_drivers.py) — intentional per module-private pattern; future refactor could extract to a shared internal module if count grows

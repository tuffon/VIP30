## v1.1 Requirements

**Defined:** 2026-02-13
**Core Value:** Reliable end-to-end bid comparison that produces actionable output

### Database

- [x] **DB-01**: PostgreSQL instance provisioned on Render
- [x] **DB-02**: SQLModel ORM with Alembic migrations (no create_all in production)
- [x] **DB-03**: Async session factory with connection pooling configured
- [x] **DB-04**: All tables have workspace_id foreign key for tenant isolation
- [x] **DB-05**: credit_grants table (workspace_id, amount, source, timestamp)
- [x] **DB-06**: credit_consumptions table (workspace_id, job_id UNIQUE, amount, timestamp)

### Workspace

- [x] **WS-01**: Workspace created automatically when user signs up
- [x] **WS-02**: User belongs to exactly one workspace
- [x] **WS-03**: All data (jobs, credits) scoped to workspace via workspace_id
- [x] **WS-04**: Enforce 1 user per workspace limit (MVP)
- [x] **WS-05**: Store owner_user_id on workspace table

### Auth

- [x] **AUTH-01**: User can request OTP via email (6-digit code)
- [x] **AUTH-02**: OTP expires after 10 minutes
- [x] **AUTH-03**: Issuing new OTP invalidates all previous codes for that email
- [x] **AUTH-04**: Rate limiting: max 5 OTP requests per email per hour
- [x] **AUTH-05**: Rate limiting: max 5 verification attempts per code
- [x] **AUTH-06**: Specific error messages (expired, invalid, too many attempts)
- [x] **AUTH-07**: Store login metadata (last_login_at, login_ip, login_method)
- [x] **AUTH-08**: JWT session stored in HttpOnly + Secure + SameSite cookie

### Credits

- [x] **CRED-01**: User can view current credit balance in UI
- [x] **CRED-02**: Credits tracked via ledger (credit_grants + credit_consumptions)
- [x] **CRED-03**: Credits only consumed on successful job completion
- [x] **CRED-04**: Trial credits granted on signup (configurable: default 5)
- [x] **CRED-05**: Credit consumption is idempotent (job can only consume once)
- [x] **CRED-06**: Balance = SUM(grants) - SUM(consumptions), calculated not stored

### Jobs

- [x] **JOB-01**: Job has defined states: queued, parsing, analyzing, writing, completed, failed
- [x] **JOB-02**: Job displays progress indicator (current state + percent/step)
- [x] **JOB-03**: Failed job stores human-readable error_reason
- [x] **JOB-04**: User can retry failed job (creates new job, charges on success)
- [x] **JOB-05**: Terminal states (completed, failed) are immutable
- [x] **JOB-06**: Job cannot start if workspace has insufficient credits

### Usage

- [x] **USE-01**: User can view job history list (status, date, credit cost)
- [x] **USE-02**: User can view credit transaction history (grants + consumptions)
- [x] **USE-03**: History supports server-side pagination
- [ ] **USE-04**: History supports basic date-range filtering — DEFERRED to v1.2

### Frontend

- [x] **FE-01**: Auth UI: email entry screen and OTP verification screen
- [x] **FE-02**: Credit balance displayed prominently in UI
- [x] **FE-03**: Job progress shown with polling/real-time updates
- [x] **FE-04**: Rebrand: UI copy reflects "bid comparison tool" positioning
- [x] **FE-05**: Clear empty state: "No jobs yet" when history is empty
- [x] **FE-06**: Clear error states: failed job, expired OTP, insufficient credits

### Internal Naming

- [~] **NAME-01**: Rename vip_job → comparison_job in codebase — PARTIAL (new code uses correct names)
- [ ] **NAME-02**: Rename raw_upload → bid_input in codebase — DEFERRED to v1.2
- [x] **NAME-03**: Update user-facing strings (UI labels, API responses, logs, errors)

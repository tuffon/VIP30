# Milestone v1.1: MVP Launch

**Status:** ✅ SHIPPED 2026-02-14
**Phases:** 1-4
**Total Plans:** 8

## Overview

Transform the existing bid comparison tool into a customer-ready MVP with user authentication, credit-based usage tracking, and real-time job progress. Four phases build sequentially: database foundation, auth system, job/credit integration, and frontend polish.

## Phases

### Phase 1: Database + Workspace Foundation

**Goal:** PostgreSQL infrastructure with workspace-scoped schema for all entities
**Depends on:** Nothing (first phase)
**Plans:** 1 plan

Plans:
- [x] 01-01: PostgreSQL setup and SQLModel models

**Details:**
- PostgreSQL instance running on Render with DATABASE_URL configured
- Alembic migrations create workspaces, users, credit_grants, credit_consumptions tables
- All tables have workspace_id foreign key enforced
- Async session factory with connection pooling handles concurrent requests
- workspace table has owner_user_id column

**Requirements:** DB-01, DB-02, DB-03, DB-04, DB-05, DB-06, WS-02, WS-03, WS-04, WS-05

### Phase 2: Auth + Workspace Creation

**Goal:** Email OTP authentication that creates user + workspace + trial credits on first login
**Depends on:** Phase 1
**Plans:** 2 plans

Plans:
- [x] 02-01: OTP send/verify endpoints with rate limiting
- [x] 02-02: JWT sessions and workspace creation flow

**Details:**
- User can request 6-digit OTP via email
- Valid OTP creates user + workspace (if new) with trial credits
- JWT stored in HttpOnly cookie persists session across refresh
- Rate limiting blocks excessive OTP requests (5/hour) and attempts (5/code)
- Specific error messages for expired, invalid, too many attempts
- Login metadata (last_login_at, login_ip, login_method) stored

**Requirements:** AUTH-01, AUTH-02, AUTH-03, AUTH-04, AUTH-05, AUTH-06, AUTH-07, AUTH-08, WS-01, CRED-04

### Phase 3: Jobs + Credits Integration

**Goal:** Job state machine with idempotent credit consumption on successful completion
**Depends on:** Phase 2
**Plans:** 2 plans

Plans:
- [x] 03-01: ComparisonJob model and state machine
- [x] 03-02: Credit consumption integration with worker

**Details:**
- Job progresses through states: queued → parsing → analyzing → writing → completed|failed
- Job displays progress (state + percent) queryable via API
- Credits consumed only on successful completion (not on failure)
- Credit consumption is idempotent (UNIQUE job_id constraint)
- Failed jobs can be retried (creates new job)
- Job cannot start if workspace balance < 1 credit

**Requirements:** JOB-01, JOB-02, JOB-03, JOB-04, JOB-05, JOB-06, CRED-02, CRED-03, CRED-05, CRED-06

### Phase 4: Frontend + Usage + Polish

**Goal:** Complete user experience with auth UI, credit display, history, and rebrand
**Depends on:** Phase 3
**Plans:** 3 plans

Plans:
- [x] 04-01: Auth UI and credit display

## Milestone Summary

**Key Decisions:**
- Workspace model from day one (1 user per workspace for MVP)
- Credits belong to workspace, not user
- Email OTP over magic links (better UX per research)
- Ledger-style credits: credit_grants + credit_consumptions
- Fixed job state machine: queued → parsing → analyzing → writing → completed|failed
- JWT in HttpOnly cookie for session management
- Idempotent credit consumption via UNIQUE job_id constraint

**Issues Resolved:**
- OTP rate limiting prevents abuse
- Credit consumption idempotency prevents double-charging
- Job retry creates new job (never re-runs old job)

**Issues Deferred:**
- USE-04: Date-range filtering for history (defer to v1.2)
- NAME-01/NAME-02: Full internal naming cleanup (partial - new code uses correct names)

**Technical Debt Incurred:**
- POST /render/upload-url is unauthenticated
- datetime.utcnow() deprecated in Python 3.12+
- JWT_SECRET has default value (should enforce in production)
- Frontend build not verified due to local Corepack/pnpm issues

# Milestone v2.4: Parser Coverage

**Status:** ✅ SHIPPED 2026-03-09
**Phases:** 23-25
**Total Plans:** 6

## Overview

Three phases to measure Xactimate parser coverage before writing a single line of parser fix code. Audit all PDFs in `./docs/` through the existing parser. Produce human-verified golden master JSON files representing the complete expected output per document type. Build an automated coverage harness comparing live parser output against golden masters and producing a structured gap report — the direct input to v2.5 parser fixes.

## Phases

### Phase 23: Parser Audit

**Goal**: Run all PDFs in `./docs/` through the existing parser and document what is captured vs. missed per document type
**Depends on**: Existing codebase (packages/parser/)
**Requirements**: AUDIT-01, AUDIT-02, AUDIT-03, AUDIT-04, AUDIT-05, AUDIT-06
**Plans**: 2 plans

Plans:
- [x] 23-01: Explore parser codebase — entry points, output schema, invoke standalone on each PDF
- [x] 23-02: Compare parser output vs. PDF content per doc type — produce structured gap inventory

**Details:**
- `audit_all.py` (219 lines) — runs XactimateRoughDraftParser on all 6 PDFs, writes per-file run_log.json
- All 6 PDFs parsed successfully: 2 rough drafts (32/40 sections, 525/887 items), 1 contractor final (0 sections — gap finding), 3 StateFarm finals (31-36 sections, 32-518 items)
- `AUDIT-REPORT.md` (255 lines) — field-by-field coverage tables for all 3 doc types, 10-item gap priority table for v2.5
- Root cause confirmed: contractor-final uses RESET/REMOVE/REPLACE column schema; StateFarm Customer Copy uses grouped-row layout
- Rough-draft parser confirmed as production-quality baseline: zero validation delta across all 72 sections

## Milestone Summary

**Key Decisions:**

- Rough-draft parser confirmed as production-quality baseline — zero validation delta; no changes needed for v2.4
- BSchacter (0 sections) is a gap finding, not a parser crash — column schema mismatch, fix is v2.5 scope
- StateFarm Customer Copy under-extraction: grouped-row layout not matched by item regex; fix is v2.5 scope
- Final-draft golden masters built via pdfplumber (not parser output) — they represent ideal target output for v2.5
- Golden master naming: SF_BSchacter.golden.json (not customer_copy — PDF was renamed during Phase 24)
- item_number=None fixed for Labor Minimums items (32, 267, 337) — Xactimate retires item numbers when items deleted; gaps in sequence are expected

**Issues Resolved:**

- Windows cp1252 stdout encoding crash: all scripts include `sys.stdout = io.TextIOWrapper(...)` fix
- Spurious CLEANING header item removed from SF_BSchacter Entrance section
